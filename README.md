# Семейный атлас

Закрытый сайт для рабочего генеалогического исследования: семейное древо, отдельные версии родства, сравнение оснований и каталог документов с сохранёнными копиями.

## Данные

Репозиторий содержит только код. Имена, даты, отношения, семейные рассказы и сканы поступают из внешнего каталога дела `Genealogy` во время сборки. `dist/`, `.private/`, пароли и архивы исключены из Git. Внешних шрифтов, аналитики, API и CDN на сайте нет.

```sh
python scripts/build.py --case /path/to/Genealogy --out dist
npm test
npm run check
python -m http.server 4173 --bind 127.0.0.1 --directory dist
```

Python 3.10+, Node.js 20+. Для самого сайта библиотеки и сервер приложений не нужны.

Каталог дела должен содержать `evidence.json`, `presentation.json` и `sources/`. В `presentation.json` хранятся понятные названия документов, роли семейных людей, объяснения каждой версии, ограничения и выбранные копии. Это отдельный слой представления: он не меняет доказательность исходных утверждений. Сборка и проверка модели требуют полного покрытия людей, версий и источников.

Основные маршруты: `#tree`, `#people`, `#candidates`, `#sources`; отдельные страницы — `#person/<id>` и `#source/<id>`. На телефоне древо сначала показывается списком поколений. Принципы структуры и основания решений описаны в [docs/ux-normalization.md](docs/ux-normalization.md).

## Доказательность

- Семейные родства показываются пунктиром и подписаны как сведения семьи.
- Гипотезы совпадения кандидатов не добавляют родительские связи.
- Разные карточки Якова с конфликтующими датами остаются отдельными записями.
- Исправленные версии доступны в истории человека.
- У источника есть URL/шифр, дата просмотра, тип, пределы проверки, файлы и выдержки.

## Развёртывание

Проект: `/opt/familytree`. Статические версии: `site/releases/<version>`, текущая версия — символьная ссылка `site/current`. `compose.yaml` поднимает внутренний Caddy только на `127.0.0.1:8094`. Внешний Caddy выдаёт HTTPS и проверяет пароль на **всех** маршрутах, включая JSON, сканы и healthz. Пример правил и инструменты развёртывания находятся в `deploy/`.

Семейные данные доставляются отдельно от Git по SSH и остаются за той же аутентификацией, что и интерфейс. На сервере не используется SSH-ключ пользователя: он остаётся на его компьютере.

Откат: переключить `site/current` на предыдущую проверенную версию; контейнер и внешний Caddy не нужно перезапускать. Перед изменением внешнего Caddy сохраняется резервная копия, конфигурация валидируется и применяется штатным reload.
